Documentation 04 - Build and launch plan

Build and launch plan

Platform choice, where to register the domain, where to host, the security headers the host must set, and the phased route from the current scaffold to a live site.

Platform: custom build or Wix?

Both reference studios run Wix (document 05), so this deserves a straight answer rather than an assumption.

The question that actually decides it Not "which is better" - custom wins on most rows. It is who edits this site in two years? If the answer is the studio owner working alone, Wix is the honest recommendation and the extra $20 a month buys real independence. If a developer is committed to it - which is the premise here - build custom, and the advantages are all real.

Middle path worth considering: build custom, but move the frequently-changing content - the status strip, the queue table, portfolio entries - into small JSON or Markdown files with a short README on editing them. It keeps the design custom while making routine updates a text edit rather than a code change.

Recommendation: custom static site, on the premise that a developer is maintaining it, with the editable-content files above as a hedge.

Prices are approximate as of mid-2026 and should be confirmed at purchase; ICANN fees and registry pricing change.

Recommendation Porkbun, unless Cloudflare Pages is chosen for hosting - in which case Cloudflare Registrar, since the DNS is already there and the pricing is the best available. Either way:
  • Register starshipsuits.com as the primary.
  • Enable WHOIS privacy before the record goes live, not afterwards.
  • Turn on the registrar lock and two-factor authentication on the registrar account.
  • Register for 2-3 years, not 1 - it is cheap insurance against a lapsed renewal, and Heckhoundz's domain expires within twelve months of registration.
  • Set a calendar reminder 60 days before expiry regardless of auto-renew.
  • Keep the registrar separate from the host. The single most valuable structural lesson from document 05.

Security headers the production host must set

Neither reference site sets any of these, because Wix does not let its customers do so. This is free ground and takes about ten minutes.

Cloudflare Pages or Netlify - _headers

/*
  Content-Security-Policy: default-src 'self'; base-uri 'none'; object-src 'none'; frame-ancestors 'none'; img-src 'self' data:; style-src 'self'; script-src 'self'; form-action 'self'
  Strict-Transport-Security: max-age=31536000; includeSubDomains
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: geolocation=(), microphone=(), camera=(), interest-cohort=()
  Cross-Origin-Opener-Policy: same-origin

/assets/*
  Cache-Control: public, max-age=31536000, immutable

nginx equivalent, if self-hosted

add_header Content-Security-Policy "default-src 'self'; base-uri 'none'; object-src 'none'; frame-ancestors 'none'; img-src 'self' data:; style-src 'self'; script-src 'self'; form-action 'self'" always;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;
Adjust the policy when third parties are added The policy above assumes the site loads nothing from anywhere else, which is the intended design. Adding analytics, an embedded video, a map, or a third-party form service each requires widening it. Widen it deliberately, one origin at a time - never relax to a wildcard to make something work. Fonts must be self-hosted, which keeps font-src out of the policy entirely.

Also worth setting at the registrar or DNS: a CAA record naming the certificate authority the host uses, and DNSSEC if the registrar supports it. Heckhoundz has neither.

Phases

Phase 0 - Scaffold Done

Repository created and pushed, placeholder page, Pages staging workflow, Dependabot, licence, planning documents. Commits 33ee9ec onward.

Phase 1 - Decide Blocking

Nothing else starts until these are answered. None require a developer.

  • Pick a visual direction. Critical path.
  • Register starshipsuits.com, with WHOIS privacy on.
  • Choose the production host - Cloudflare Pages or Netlify.
  • Confirm the real commission tiers and prices.
  • Book the photography. Longest lead time of anything in this plan - start it first.

Phase 2 - Design system Next

Tokens for colour, type, spacing and radii as CSS custom properties. Self-hosted subset WOFF2 fonts committed to the repository. Core components - navigation, tier card, portfolio tile, footer, buttons - built and contrast-checked. Wordmark, favicon and social preview image.

Phase 3 - Pages Then

The seven pages from document 03, built against real content as it arrives. Home, prices and about first - they are useful even with a thin portfolio. Queue and terms last, since they depend on studio decisions rather than code.

Phase 4 - Media and forms Then

Photography processed into an AVIF and JPEG responsive pipeline. Gallery lightbox, keyboard-operable. Enquiry form wired to the chosen host's handler, with honeypot, field length caps and rate limiting.

Phase 5 - Launch Finally

Repository flipped to public, Pages staging re-enabled, DNS pointed at the production host, TLS verified, headers verified, then the checklist below.
